# Lending Pro Freeware 1.5.1 — Application Audit

Audit date: **August 13, 2026**
Scope: public source tree, local desktop runtime, browser interface, business workflows, generated documents, backups, distributable archives, privacy and dependency health.

## Technical summary

The audited 1.5.1 source is operational across the tested workflows. The full automated suite passes, the isolated runtime preserves database integrity, generated Excel and PDF files open correctly, the Windows source archive is complete, and the interface is usable at desktop and 390 px phone widths. No known npm vulnerability or broken Python dependency remains.

The audit identified and corrected four material defects: incomplete raw JSON backups, incomplete demo resets, custom component styles overriding hidden controls, and mobile toolbar/table clipping. Public sample data and repository tests were also hardened to prevent personal or regional maintainer information from being reintroduced.

## Verification evidence

### Automated and static checks

- `npm test`: **27 tests passed**.
- `npm run check`: Python compilation and JavaScript syntax checks passed.
- `npm audit`: **0 known vulnerabilities**.
- `python -m pip check`: no broken Python requirements.
- Frontend-to-backend bridge review: every referenced API method has a backend implementation.
- Current public-source privacy scan: no unapproved personal email address, maintainer attribution or local home path.

The reviewed summary values are preserved as a reproducible SQLite snapshot in `docs/audit-evidence.sql`; it is the source used by the portable audit report.

### Business workflow smoke test

An isolated application data directory was used to create a client, collector, declining-balance biweekly loan, guarantor, collateral, payment and penalty. The audit then verified:

- a reconciled 13-row amortization schedule;
- payment allocation and voiding;
- penalty creation and settlement state;
- full and selective Excel exports with the expected business sheets;
- readable contract, receipt and amortization PDFs;
- SQLite, Excel and JSON backups;
- point-in-time restore after a post-backup mutation;
- SQLite integrity and foreign-key checks with zero violations.

### Interface coverage

The dashboard, clients, loans, payments, collection calendar, overdue alerts, referral commissions, settings, help, about and system-log views were loaded and inspected without frontend errors or broken images. Interactive coverage included theme and sound toggles, calculator arithmetic, quick actions, client creation/search/detail, loan creation, payment receipt/void, contract and amortization previews, penalties, profile creation, collector creation, selective export, local backup, password protection, failed-login handling, session locking and navigation filters.

At 390 × 844 px, the header actions remain inside the viewport, the drawer opens and closes through normal interaction, navigation works, unavailable demo controls stay hidden, and the client directory retains its primary fields without page-level horizontal overflow.

### Packaging and native launch

- The Windows source ZIP contains the required launchers and application files, passes archive integrity checking, and excludes databases, logs, credentials, caches and Git metadata.
- The macOS release build is generated from the audited source, ad-hoc signed, checksum-published and inspected before upload.
- The 1.5.1 / build 8 application bundle was launched against isolated data. **Quit & Save** created the shutdown backup, closed the native window, stopped the local HTTP listener and ended the process normally.

## Boundaries and residual risks

- SMS delivery, Google Drive authorization, external map opening and camera permission prompts were not transmitted or granted during this audit. Their local validation and error-handling paths were reviewed, but complete end-to-end proof requires real third-party credentials or hardware permission.
- The macOS app is ad-hoc signed and not Apple-notarized; the documented first-launch Control-click procedure remains necessary.
- Local profile passwords protect access through the application but do not encrypt the SQLite database on disk.
- Historical tags and releases may predate the current privacy hardening. The current source and current release are the supported public baseline.

## Release recommendation

Publish 1.5.1 as the supported public release after the GitHub Actions checks pass. Future changes should retain the privacy regression test, the complete backup/restore test and the 390 px responsive smoke as release gates.
